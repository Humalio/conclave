# Console design guidelines

These rules govern every change to the operator console (`server/public/`). They are written for people and coding agents alike: follow them by default, and treat a deviation as a design decision that needs a line in [Exceptions](#exceptions).

- **What** each view must answer lives in [Dashboard UX](dashboard-ux.md). This document covers **how** it looks and behaves.
- The visual reference is the console itself: every screen follows these rules. To look at it with realistic data, run the local hub (see [Getting started](getting-started.md#local-design-review-hub)).
- When this document and the code disagree, this document wins: fix the code, or change the rule here first.

## 1. Principles

1. **One scale per property.** Sizes, weights, spacing, radii, heights and colours come from the tokens in [§2](#2-tokens). A literal value in CSS or JS that is not a token is a bug.
2. **Alignment you can measure.** Every element sits on a shared edge or the 4 px grid. If two things look almost aligned, they are misaligned.
3. **Mobile is its own layout.** Below 768 px the console is a phone app: lists, not tables; bottom navigation; sheets; actions within reach. It is never the desktop squeezed.
4. **One primary action per screen.** Everything else is secondary, tucked into an overflow, or removed. Destructive actions are never the most visible thing on a screen.
5. **Help on demand.** The UI shows names, values and states. Explanations live behind an ⓘ.
6. **Colour means state.** Colour carries status (ok, warn, bad, info) or the single accent. Never decoration, never "make the chart prettier".
7. **Show the evidence, keep the context.** Respect the evidence rules in [Dashboard UX](dashboard-ux.md#interaction-rules). Opening a detail never loses the list position, filter or selection behind it.
8. **No left accents.** Never mark a card, row, quote or callout with a coloured or thick bar on its left edge. State goes in a pill, in the words, or in the border colour of the whole box; emphasis goes in the type. Thin 1–2 px `--line`/`--line-2` rails that show nesting (a thread, a chain, an operation's details) and the muted rule of a quote in rendered Markdown are structure, not accents.

## 2. Tokens

Tokens are defined once, on `:root` in `server/public/style.css`, which is the source of truth for their values. Use them through `var(--…)`. Light theme overrides colours only; every other token is theme-independent.

### Type

| Token | Value | Use for | Never for |
|---|---|---|---|
| `--t-cap` | 500 11/16, caps + `.06em` in overlines | overlines, axis ticks, badge and tab-count text | sentences |
| `--t-meta` | 400 12/16 | secondary lines, timestamps, captions | primary values |
| `--t-body` | 400 13/20 | default text, row descriptions, messages | headings |
| `--t-label` | 500 13/20 | buttons, tabs, field labels, segment labels | body text |
| `--t-title` | 600 13/20 | card titles, row names, emphasised values | page titles |
| `--t-head` | 600 16/24, `-.01em` | the one page or app-bar title | anything else |
| `--t-lead` | 400 16/24 | the message a Needs you card leads with | titles and headings (`--t-head`) |
| `--t-num` | 600 22/28, `-.02em`, tabular | KPI numerals | inline numbers in text |
| `--t-id` | Geist Mono 400 12/16 | identifiers: tool names, ids, paths, hostnames, key prefixes, the clock | prose, labels, numbers that are not ids |

- Exactly **four sizes** (11, 12, 13, 16) plus 22 for numerals, and **three weights** (400, 500, 600). No half pixels.
- All numbers that can change use `font-variant-numeric: tabular-nums`.
- Monospace never sets a sentence. An alert message, a role or a description is prose even if it mentions an id.
- Line-heights come with the token. Never set `line-height` separately.

|---|---|---|

| Shell | `--rail` 60 px side rail (tablet and desktop) · `--scrim` behind sheets | |
| Card padding | 16 px at every breakpoint | Card title, body text and rows all start at this edge. |
| Stack | 12 px between cards | |
| Radii | `--r-sm` 6 (badges, tags, avatars, kbd) · `--r-md` 8 (buttons, inputs, segments, rows) · `--r-lg` 12 (cards, sheets, popovers) · `--r-chip` 3 (chips: pills, tags, counts and cross-reference chips; the strip segments in a paper's readiness block use 1) · `--r-full` (dots, switches) | An inner radius is always smaller than its container's. |
| Heights | rows 56 (two lines) or 44 (key-value, single line) · `--h-ctl` controls 32 desktop, 36 compact · `--h-touch` tap targets ≥ 44 on touch · `--h-bar` app bar 56 · `--h-nav` bottom nav 64 + safe area | Every height is a multiple of 4. |
| Icons | `--icon` 16 in rows and buttons · `--icon-nav` 22 in the bottom nav (inside a `--h-bar` × `--h-bar / 2` pill) | Stroke 1.75–1.8, `currentColor`. |

### Colour

| Token | Meaning |
|---|---|
| `--accent`, `--accent-soft` | The one brand colour, the logo red: primary buttons, active nav and tab, links, the selected row. Light `#ad412c`, dark `#f07a5f` (the logo's `#c4503a` shifted so text and fills pass AA on every panel). `-soft` and `--ramp-*` are the same red at low alpha. |
| `--ok` / `-t` / `-soft` | Healthy, allowed, running, online. |
| `--warn` / `-t` / `-soft` | Needs attention soon: overdue, unpaired, outside the hub. |
| `--bad` / `-t` / `-soft` | Denied, revoked, failed, destructive. |
| `--info` / `-soft` | New, informational. |
| `--on-ok` | Ink on a solid `--ok` fill (allowed cells in the access matrix). Ink on `--accent` and `--bad` fills is `--accent-ink`: white in light, near-black in dark. |
| Logo | The `#i-logo` symbol in the sprite (also the favicon) keeps its own fixed colours; it never takes the accent. |
| `--text`, `--muted`, `--faint` | Primary, secondary and tertiary text. Nothing else for text. |
| `--line`, `--line-2` | Dividers and borders. Cards use a border, not a shadow. |
| `--spark` | Sparklines and neutral data marks. Switch to a status colour only when the value is in that state. |
| `--ramp-1…4` | Sequential data in the accent hue (exposure, heat). No second hue. |

- Use `-t` variants for text on dark surfaces and `-soft` for backgrounds. Pills are always a `-soft` background with `-t` text.
- Never show the same status in two colours, or two statuses in the same colour.
- Shadows exist only on floating layers (sheets, popovers, menus, toasts): `--shadow-pop`.

## 3. Layout and alignment rules

These are checkable. The [review checklist](#9-review-checklist) measures them.

1. **One text edge per card.** The card title, its body text, row names and section overlines all start at the card's 16 px padding.
2. **Leading column.** Rows that start with an avatar, icon or dot put it in a fixed-width leading column (32 px for avatars and icons, 8 px for dots, plus a 12 px gap), so the text after it lines up from row to row.
3. **Trailing edge.** Everything on the right of a row (time, count, pill, chevron, switch, action) ends on the card's right padding. If one row has a chevron, every navigable row in that list has one.
4. **Numbers right-aligned and tabular** in lists, tables and stat columns. Stat grids share column tracks between their rows, so a 3-column row never sits under a 4-column row.
5. **Vertical centring.** Avatars spanning two lines centre on the two-line block. Dots and pills centre on the first text line (the name), not on the row.
6. **Fixed heights.** Two-line rows are exactly 56 px including their 1 px divider (for example `height:56px; padding:7px 0 8px` with a top border). Single-line rows are 44 px.
7. **Baselines.** A value with a unit or denominator ("0 /6", "93 %") sits on one baseline. Use `align-items: baseline`, not padding nudges.
8. **No orphans.** No grid leaves a single tile alone on its last row, and no button sits alone on a row because its neighbour wrapped.
9. **No sideways scroll** of the page at 360 px. Wide content (code, markdown tables) scrolls inside its own bordered box.
10. **Truncation is a decision.** Text that is not a single-line field wraps inside its card: a long word, URL, id or path breaks where it does not fit (`.sec` sets `overflow-wrap: break-word`, and its tags may wrap), so nothing leaves its card or widens the page. A single-line field truncates with an ellipsis and exposes the full value (`title` or the detail view). Never truncate mid-identifier when the end is what distinguishes it; truncate in the middle instead (`ah_ses_didl…3s`).

## 4. Breakpoints and mobile

Three breakpoints only. Write each `@media` block next to the component it changes.

| Range | Name | Shell |
|---|---|---|
| < 768 px | **phone** | App bar (56) + bottom nav (64 + `env(safe-area-inset-bottom)`). Lists replace tables. Sheets replace popovers and modals. |
| 768–1179 px | **tablet** | Side rail, two-column grid. |
| ≥ 1180 px | **desktop** | Side rail, 12-column grid, 24 px gutters. |

Phone rules:

- **Bottom nav** has the same four destinations as the desktop rail: Work, Vault, Security, Audit. Home is not a destination of its own: it is Work's first tab (before Topology), and the hub opens on it. There is no Teams tab: the team list is the Teams card on Home. The active item follows the area of the current screen, including detail screens: a task is in Work, a key in Security, Lockdown in Security.
- **App bar:** title (`--t-head`) on the left. On the right go the live clock (`--t-id`, muted) and one overflow button (40×40). Lockdown, two-factor, theme, shortcuts and sign-out live in the overflow sheet, with labels. A pending account issue (2FA not enrolled) shows as an 8 px dot on the overflow button.
- **Detail app bar** for any screen with a parent: back (40×40, `aria-label` "Back to <target>"), title (one line) with a meta line under it, overflow. The meta line is the collapsed parent trail ("Home › … › Conclave Developers"), then the screen's own count or state after a middle dot; screens write no meta of their own. Destructive actions (Revoke, Archive, Stop, End logins, Suspend) live in that overflow sheet.
- **Tabs** scroll horizontally with a 24 px fade on the clipped edge. Never wrap tabs and never clip without the fade. Workspace switchers with ≤ 4 short labels may use an equal-width segmented control instead.
- **Tables become list rows** (§5). A column that matters goes into the row's meta line; a column that does not is dropped on phones.
- **Primary actions stay reachable.** Form submits and the screen's main action sit in a sticky action bar directly above the bottom nav, never under it.
- **One row of filters:** a segmented control plus a filter button that opens a sheet. Date ranges, selects and secondary filters go in that sheet.
- **No nested scrolling.** Only the page scrolls. The one exception is wide content inside its own box (rule 3.9).
- **Keyboard-only features** (shortcuts) are hidden on touch devices (`@media (hover: none)`).
- **Tap targets ≥ 44 px.** A 16 px icon button gets its 44 px through padding or negative margin, not a bigger icon.

### Markdown contexts

Agent text is L2 and may hold Markdown. Every field that shows it uses one of three contexts, each with one helper in `app.js` around the renderer in [md.js](../server/public/md.js). Never show agent text through `esc()` alone when it may hold Markdown, because the reader would see the raw `**` and backticks. Never build its HTML any other way.

| Context | Helper | Used for | What it shows |
|---|---|---|---|
| Plain | `mdText()` | Labels, titles, short task summaries ("In short"), row meta lines, previews cut to a length; in the Blueprint, item titles (item head, rows, chains, cards, proposal changes), row meta such as a hypothesis's criteria or statement, and row tooltips; alert messages (Home's most urgent card, the Alerts list, an in-page alert) and Needs you row titles and reasons, which often quote a Blueprint change note or a report | Text only: marks, link targets and escapes are dropped, a formula shows its source without the `$` signs, and the result is escaped. |
| Inline | `proseLine()`, `rowLine()` | One-line field values and option effects (`proseLine`), a Blueprint decision's option labels and their pros and cons, compact rows whose whole row is a button (`rowLine`) | Emphasis, code, highlights, tags and inline maths. `proseLine` keeps links. `rowLine` shows a link as its label, because a row button cannot hold a link. |
| Full document | `prose()`, `mdDoc()` | Criteria (given, when, then; hypothesis criteria in detail), briefs, submitted task summaries, records, playbooks, decision context, reports, vault notes | Every supported block: headings, lists, tasks, tables, quotes, callouts, code, diagrams, maths. Vault links are resolved for the viewer. |

Some text stays as written on purpose: identifiers (Blueprint keys, `evidence` keys, refs, `source`, glossary aliases, commit hashes and paths) show in the identifier font, escaped, never through `mdText`, which would drop the `_` and `*` they hold; edit fields keep the raw text so a save never loses markup; and agents read raw Markdown from `bp_read`. Plain text keeps code marking: a code in a title is still underlined and opens its term.

The rules hold in every context. Text is escaped before markup is added, and no raw HTML passes. Links get an `href` only for `http(s)`, a console `#route` and a resolved vault file. Every other scheme shows its label only.

### Mockups in the locked frame

A mockup attached to a task ([dashboard UX](dashboard-ux.md), task screen "Attachments") is shown in a locked frame:
the hub serves it with `sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:`, and the
console's iframe is `sandbox` too. Make one that works there:
- **One self-contained HTML file**, starting with `<!doctype html>`, at most 2 MB. The hub tells HTML from text by its
  first bytes, so a file without the doctype or `<html>` is a download, not a mockup.
- **Styles inline**, in a `<style>` element or `style` attributes. No stylesheet link, web font or CDN loads.
- **Images and fonts as `data:` URLs.** A screenshot inside a mockup is a base64 `data:image/png`; better, attach it
  as its own PNG beside the mockup, where the reviewer can open it full size.
- **No scripts.** They do not run, in the frame or in a new tab. Show each state as its own block on the page, and use
  CSS for what moves: `:hover`, `:focus`, `<details>`, `:target` for an overlay, media queries for the phone width.
- **Built from the tokens** (§2), with light and dark (`prefers-color-scheme` and `data-theme`), so the mockup shows the
  console's look. The frame is 260 px high and as wide as the card; Open in a new tab shows it full size, where media
  queries see the real width.
- **Sample data only**, never a key, a name or a screenshot of a secret. Crop or blur anything private before attaching.

## 6. Copy and help on demand

- **One line of helper text at most** (about 60 characters). Anything longer goes behind an `.info` button, written in two short sentences or fewer.
- Explain **at the point of need**: put the ⓘ next to the state it explains ("Outside the hub ⓘ"), not in a paragraph above the list.
- Labels are nouns or verbs the operator would say: "Revoke key", not "Proceed". Buttons say what happens.
- Sentence case everywhere. Overlines are the only uppercase text.
- **Dates.** Use day, abbreviated month, and 24-hour time in detail views. Use elapsed time such as “2h” in lists. Show seconds only in audit exports.
- **Counts:** "7 of 8 tasks", "0 live · 6". Use the middle dot `·` to join meta facts.
- Abbreviations like "SES", "APP" or "crd" do not appear in the UI. Spell out "Session key" and "App key".
- Empty states say what is absent ("No pending requests"), not a mood ("Clear").

## 7. Accessibility

- Contrast: text ≥ 4.5:1, large numerals and icons ≥ 3:1, in both themes.
- State is never colour-only: pills carry words, dots carry a text label or `title`.
- Every interactive element is reachable by keyboard and has a visible `:focus-visible` ring (2 px accent, 2 px offset).
- Sheets trap focus and return it to the opener. Esc closes them.
- Respect `prefers-reduced-motion`: no pulsing, flowing or scaling animations.
- Icon-only buttons have `aria-label`. Tabs use `role="tablist"` / `aria-selected`, and the nav uses `aria-current="page"`.

## 8. Code rules

- **No inline `style=""`** in `app.js` templates except computed geometry (widths of progress bars, chart coordinates). Everything else is a class.
- **Tokens only.** No raw px font sizes, radii, weights or colours in CSS rules; spacing uses `--s*`. New tokens go into [§2](#2-tokens) and `tokens.css` in the same change.
- One CSS block per component in `style.css`, ordered as in [§5](#5-components), with its `@media` rules next to it.
- Render shared components through small helpers in `app.js` (for example `row()`, `kv()`, `pill()`, `sheet()`, `info()`), so markup and ARIA stay identical everywhere.
- Text content goes through `esc()`. Never build HTML from unescaped data.
- Never break a working flow for looks. Behaviour, data, routes and keyboard shortcuts stay as they are unless the user asked for the change.

## 9. Review checklist

Run these before calling a UI change done, at 390 px and at 1440 px, on a hub with data (`npm run dev:hub` + `npm run dev:seed`, see [Getting started](getting-started.md)).

- [ ] No page-level horizontal scroll at 360 px: `document.documentElement.scrollWidth === innerWidth`.
- [ ] Two-line rows measure exactly 56 px and single-line rows 44 px.
- [ ] Trailing items in a list share one right edge (equal `getBoundingClientRect().right`).
- [ ] A team or project screen's header is one 56 px row at 1440 px, and with a long title and a deep trail its actions stay on that row.
- [ ] The trail names every ancestor from the root tab, and Back (‹, the phone app bar, the context bar) goes to the target its `aria-label` names.
- [ ] A list row with an agent has **Message** in its trail, before More, for admins.
- [ ] Only token font sizes are in use: collect computed `font-size` and `font-weight` of all text nodes on the screen; nothing outside 11/12/13/16/22 and 400/500/600.
- [ ] The bottom nav highlights the area the screen belongs to.
- [ ] The primary action is visible without scrolling or sits in the action bar; no destructive action is outside an overflow or confirm.
- [ ] No inline helper text longer than about 60 characters.
- [ ] Agent text shows in its [Markdown context](#markdown-contexts): no raw `**` or backticks on screen, and no link inside a row button.
- [ ] Keyboard: Tab reaches every control in order; Esc closes sheets; focus returns.
- [ ] Light theme checked once.
- [ ] No console errors.
